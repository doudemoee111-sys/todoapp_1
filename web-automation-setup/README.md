# PCを消してもWebだけで自動化を回す ― 移行キット

**対象:** FactSpark 動画自動生成パイプライン（`video-automation`）＋ 関連タスク
**ゴール:** パソコンの電源を落としても、毎日の動画生成・投稿がクラウド（Claude Code Routines）だけで自動で回り、スマホ・ブラウザから確認できる状態にする。
**このキットの作成日:** 2026-08-13

---

## 🚦 いちばん大事なこと（先に読んでください）

あなたのやりたいこと（PCを消してWebだけで回す／今のローカル版を削除する）は**実現できます**。
ただし、次の順番を守らないと**取り返しがつかなくなります**。

> ### ⚠️ ローカルの `video-automation` フォルダは、まだ絶対に消さないでください
>
> 今このフォルダは、あなたの**唯一のコード**であり、**APIキーとYouTubeログイン情報の唯一の置き場所**です。
> GitHubにも、どのクラウドにも、まだコピーが存在しません。
>
> **削除してよいのは、次の2つが両方できたあと**です:
> 1. コードがGitHubに上がったことを確認できた
> 2. クラウド版が実際に動画を1本作れた（テスト成功）ことを確認できた
>
> それまでは、電源を切る（スリープ）のはOKですが、**フォルダの中身は消さないでください**。

---

## なぜ「PCで1回だけ作業」が必要なのか

クラウド自動化（Claude Code Routines）は、**GitHubに置いたコードを毎回取ってきて実行する**仕組みです。
つまり「コードがGitHubにあること」が大前提です。

いまコードはあなたのPCの中だけにあります。私（クラウド側のClaude）は、あなたのPCの中には入れません。
なので、**PCからGitHubへコードを上げる最初の1回だけ**は、PC側で作業する必要があります。

同じ理由で、**YouTubeへの初回ログイン許可**もPC（ブラウザのある端末）で1回だけ必要です。
ただしこれは、既にお持ちの `token.json` の中身をコピーするだけで済む可能性が高いです（後述）。

**この2つ（コードのアップロード＋鍵のコピー）が終われば、以降はPCの電源に一切関係なく、クラウドだけで動きます。**

---

## 全体の流れ（6ステップ）

| ステップ | 何をする | 作業する場所 | 目安 |
|---|---|---|---|
| **Step 1** | コードをGitHubに上げる | PC（1回だけ） | 15分 |
| **Step 2** | APIキー・YouTube鍵をクラウドの「秘密情報」に登録 | Web | 15分 |
| **Step 3** | クラウド用にコードを少し改修（ローカルのClaude Codeに任せる） | PC or Web | 30分 |
| **Step 4** | 「クラウド環境」を作り、ネットワーク許可を設定 | Web | 10分 |
| **Step 5** | Routine（自動実行）を3つ登録し、テスト実行 | Web | 20分 |
| **Step 6** | 数日〜1週間並行で様子を見て、問題なければローカルを停止・削除 | Web | ― |

各ステップの詳細は下に続きます。専門的な作業（コード改修）は、**あなたのPCで開いているClaude Codeにこのフォルダの指示文を渡すだけ**で済むように用意してあります。

---

## Step 1 ― コードをGitHubに上げる（PCで1回だけ）

**目的:** クラウドがコードを取ってこられるようにする。**同時に、コードのバックアップにもなります**（だから削除前に必ずやる）。

1. GitHubで新しいリポジトリ（コードの保管場所）を作ります。
   - リポジトリ名の例: `video-automation`
   - **公開範囲は「Private（非公開）」を選んでください**（他人に見られないように）。
2. PCで開いているClaude Codeに、次のようにお願いします（コピペでOK）:

   ```
   このvideo-automationフォルダをGitHubのリポジトリ（video-automation, Private）に上げてください。
   ただし、APIキーとログイン情報は絶対に含めないでください。
   具体的には *_api_key.txt / token.json / client_secret.json / *.json のうち秘密情報を、
   このフォルダの assets/gitignore.sample を参考に .gitignore で除外してから push してください。
   push が終わったら、除外できているか（秘密情報がGitHub上に無いか）を確認して報告してください。
   ```

3. アップロード後、GitHub上で `*_api_key.txt` や `token.json` が**含まれていないこと**を必ず目視で確認します。
   → もし1つでも上がっていたら、その鍵は漏れた扱いになるので、各サービスで作り直してください。

> 💡 このキットの `assets/gitignore.sample` が、除外すべきファイルの一覧です。

---

## Step 2 ― 鍵（秘密情報）をクラウドに登録する（Web）

クラウドでは、APIキーをファイルではなく「秘密情報（Secrets / 環境変数）」として登録します。
`claude.ai/code` の環境設定画面で、次の**7つ**を登録します。

| 登録名（環境変数名） | 中身のありか（ローカル） |
|---|---|
| `ANTHROPIC_API_KEY` | `generator/anthropic_api_key.txt` |
| `OPENAI_API_KEY` | `generator/openai_api_key.txt` |
| `STABILITY_API_KEY` | `generator/stability_api_key.txt` |
| `YOUTUBE_RESEARCH_API_KEY` | `research/api_key.txt` |
| `YOUTUBE_CLIENT_ID` | `generator/client_secret.json` の中の `client_id` |
| `YOUTUBE_CLIENT_SECRET` | `generator/client_secret.json` の中の `client_secret` |
| `YOUTUBE_REFRESH_TOKEN` | `generator/token.json` の中の `refresh_token` |

**YouTubeの鍵（下3つ）について:**
`token.json` の中に既に `refresh_token` という項目があるはずです（2026-08-10にOAuthを「本番」ステータスへ移行済みのため、有効期限切れの心配はほぼ無くなっています）。
その値をそのままコピーして `YOUTUBE_REFRESH_TOKEN` に入れれば、**ブラウザでの再ログインは不要**です。

もし `token.json` に `refresh_token` が見当たらない場合だけ、PCで一度
`python -u youtube_upload.py` を実行して再ログインし、新しく発行された `token.json` から値を取ります。

> 📄 登録すべき鍵の一覧は `assets/reference_secrets_and_network.md` にもまとめてあります。

## Step 3 ― クラウド用にコードを少し改修する

クラウド（Linux）はWindowsとは環境が違うため、4か所だけ直します。
**あなたが手で直す必要はありません。** ローカルのClaude Codeに `assets/code-changes.md` を渡せば、そのとおりに直してくれます。

直す4か所の要点:

1. **鍵の読み込み方**: ファイル（`*_api_key.txt`）→ 環境変数（Step 2で登録した秘密情報）から読むように。
   （ローカルでも動くよう、環境変数が無ければ従来のファイルを読むフォールバックも残す）
2. **動画の保存先**: `E:\ショート動画保存場所` → クラウドでは一時フォルダに。動画はYouTubeへ上げたら消してOKなので保存場所は要りません。
3. **字幕フォント**: WindowsのメイリオボールドはLinuxに無いため、`Noto Sans JP Bold` を使うように切り替え（`setup.sh` で自動導入）。見た目が少し変わる可能性があるので、テスト時に1本だけ目視確認します。
4. **過去タイトルの管理（topic_history.json）**: クラウドは毎回コードを取り直すのでファイル追記が引き継げません。
   → **おすすめ（案A）:** ファイルをやめ、実行のたびにYouTubeから最近の投稿タイトルを取得して「ネタ被り」を判定する方式に変更。状態ファイルが不要になり、いちばんシンプルです。

ローカルのClaude Codeへの依頼文（コピペ用）:

```
このフォルダの web-automation-setup/assets/code-changes.md に書かれた1〜4の改修を、
既存の挙動を壊さないように（ローカルでも今までどおり動くように）適用してください。
各変更のあと、ローカルで軽く動作確認して、変更点を要約して報告してください。
```

## Step 4 ― クラウド環境を作り、ネットワークを許可する（Web）

Routineは「クラウド環境」の上で動きます。既定ではインターネットの通信先が制限されているので、
このパイプラインが使う通信先を**明示的に許可**します。

`claude.ai/code` の環境設定で、ネットワークアクセスを **Custom** にし、次のドメインを許可します:

- `api.anthropic.com` … 台本生成（Claude）
- `api.openai.com` … ナレーション音声（TTS）
- `api.stability.ai` … 背景画像生成
- `www.googleapis.com` … YouTubeアップロード・リサーチ
- `oauth2.googleapis.com` … YouTubeログインの更新

さらに、環境の**セットアップスクリプト**に `assets/setup.sh` の内容を設定します。
これで、動画合成に必要な `ffmpeg`・日本語フォント・Pythonライブラリが毎回自動で用意されます。

> 📄 許可ドメインの一覧は `assets/reference_secrets_and_network.md` にもあります。

## Step 5 ― Routine（自動実行）を登録してテストする（Web）

`claude.ai/code/routines` で、次の3つを登録します。プロンプト（指示文）は `assets/routine-prompts.md` にコピペ用で用意しています。

| Routine | 実行時刻（日本時間） | 役割 |
|---|---|---|
| **ShortsResearchAndPromptTuning** | 毎日 5:00 | ジャンルリサーチ＋台本プロンプト調整 |
| **ShortsAutoRoutine** | 毎日 6:00 | 動画5〜10本の生成・YouTube予約投稿 |
| **ShortsDailyRoutineCheck** | 毎日 7:00 | 前日の結果ヘルスチェック |

> ⏰ 時刻は日本時間（JST）で入力すれば、Web側が自動でUTCに換算してくれます。

**必ず先にテスト実行を:**
本番スケジュールを入れる前に、まず ShortsAutoRoutine を **「Run now（今すぐ実行）」** で1回動かします。確認すること:

- 動画が1本ちゃんと生成され、YouTubeに**非公開（private）＋予約**で上がるか
- 字幕フォント（Noto Sans JP Bold）の見た目が許容できるか（1本だけフレームを目視）
- 1本あたりの所要時間（ローカルでは2〜4分。クラウドで極端に遅くないか）

> 🧪 テスト動画は本番の投稿枠を汚さないよう、確認後すぐ削除する前提で回すのがおすすめです。

## Step 6 ― 並行稼働 → ローカル停止・削除（安全確認）

いきなりローカルを消さず、**数日〜1週間は「クラウドとローカルを両方動かす」**か、
少なくとも**クラウドが数日連続で成功する**のを確認します。

問題が無いと確認できたら:

1. Windowsタスクスケジューラの3ジョブ（ShortsAutoRoutine / ShortsDailyRoutineCheck / ShortsResearchAndPromptTuning）を**無効化**します。
2. 数日、クラウドだけで問題が出ないことを確認します。
3. **ここで初めて**、ローカルの `video-automation` フォルダを削除してよい状態になります。
   （コードはGitHubに、鍵はクラウド秘密情報に、動画はYouTubeにある＝ローカルに残すものは無い状態）

> ✅ 削除前チェックリスト
> - [ ] GitHubにコードがある（秘密情報は含まれていない）
> - [ ] 7つの秘密情報がクラウドに登録済み
> - [ ] クラウドのRoutineが**数日連続で**成功している
> - [ ] YouTubeに予約投稿が想定どおり並んでいる

## 補足：動画パイプライン以外のタスクについて

引き継ぎ書には、動画以外に Cowork のスケジュールタスクもありました。今回の「PCを消す」目的での扱いを整理します。

| タスク | 今の状態 | クラウド化の要点 |
|---|---|---|
| gmail-daily-triage | Coworkクラウドで稼働 | ローカル依存なし。ほぼそのままRoutine化できる（優先度：低い手間） |
| shorts-daily-routine-check / research | **Cowork版とローカル版が二重稼働の疑い**（要確認） | まずCowork側を無効化して重複を解消。上記Step5で一本化 |
| record-stock-prices | E:ドライブのExcelに書き込み | 保存先を Google スプレッドシート に変えればクラウド化可能 |
| toeic-daily-practice | E:ドライブにWord保存 | 保存先を Google ドライブ に変えればクラウド化可能 |
| x-daily-draft-posts | 無効化中 | 対応不要（再開時に同様の移行） |

「PCを消す」ために**必須なのは、Windowsタスクスケジューラで動いている動画パイプライン3ジョブの移行**です（Step1〜6）。
Excel/Word保存の2タスクは、消す前に保存先をGoogleへ移す一手間が必要なので、動画パイプラインが安定してから着手するのがおすすめです。

## まだ決めていない点（おすすめを添えて）

引き継ぎ書で「要確認」だった項目に、あなたの希望（Web完結・ローカル削除）を踏まえたおすすめを付けます。変更したい場合だけ教えてください。

| 決めること | おすすめ | 理由 |
|---|---|---|
| 過去タイトルの管理 | **案A：YouTubeから都度取得** | 状態ファイル不要でいちばんシンプル。ローカル削除と相性が良い |
| 台本プロンプトの自動反映 | **案A：mainへ直接反映** | 現行運用に一番近く、翌朝の生成に確実に反映される |
| 動画のローカル保存 | **不要** | YouTubeに上がるので手元保存は要らない（削除方針と一致） |
| 並行稼働の期間 | **最低3〜7日** | クラウドの安定を確認してから削除するため |
| コスト上限 | **要確認** | Routine実行はClaude Codeの利用枠を消費。月の上限だけ決めておくと安心 |

### 私（クラウド側）ができること・できないこと

- **できないこと:** あなたのPCの中には入れないため、Step 1（GitHubへの初回アップロード）とStep 2の鍵のコピー元取得は、PC側の作業になります。
- **できること:** 上記以外の設計・手順・改修指示・プロンプトはすべて用意しました。GitHubにコードが上がって、そのリポジトリに私がアクセスできるようになれば、**コード改修（Step 3）も私が実際に行えます** ―― そのときは「video-automationリポジトリにアクセスできるようにしたので、続きをやって」と声をかけてください。
