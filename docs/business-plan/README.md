# 副業ビジネス提案：AI検索可視化（GEO/LLMO）プロダクタイズド・サービス → SaaS化

作成日：2026-08-23 / 調査・分析：Claude Code

---

## 0. 結論（3行）

**「AI検索（ChatGPT・Gemini・AI Overviews）に自社が引用されているかを診断し、引用されるように直す」月額サービスを、納品工程をAIで完全自動化して1人で運営する。**

まず高単価サービス（月5〜30万円）で3か月以内にキャッシュを作り、同じ自動化エンジンをそのままセルフサーブSaaS（月9,800円〜）に転用して年商1億円レンジまでスケールさせる、2段ロケット構成。

初期投資は**約23万円（3か月累計）**、損益分岐は**3社契約**。

## 2. なぜ今このマーケットなのか（市場分析）

### 2-1. 「検索が壊れた」ことが確定した2年間

| 指標 | 数値 | 意味 |
|---|---|---|
| AI検索エンジンの国内セッション数 | 2024年4月比 **+5,535%**（2026年4月） | 2年で55倍。チャネルとして無視できない規模に |
| AI検索の国内シェア | ChatGPT 約59%、Gemini上昇継続（2026年4月） | 最適化先が複数化＝支援ニーズが複雑化 |
| ゼロクリック率 | Google検索の**約60%**、モバイル**77%** | サイトに人が来ない |
| 順位維持時のCTR | **約40%減** | 「SEOは成功しているのに売上が落ちる」現象 |

これは事業者にとって**「順位は1位なのに問い合わせが半減した」**という、原因不明の売上減として体感される。原因を説明でき、打ち手を出せる人間が圧倒的に足りていない。**これが本案の収益源**である。

### 2-2. 価格が既に立っている＝市場が成立している

- LLMO/GEO対策の外注相場：**初期費用10〜50万円／月額10〜100万円（中心帯20〜30万円）**
- 主要5社の公開料金：初期10〜50万円、月額20〜80万円
- MEO（ローカル検索）対策：月額3〜10万円、初期0〜30万円

**新ジャンルにもかかわらず既に高単価の相場が形成済み**。これは「教育コストを自分で払わなくてよい」ことを意味し、3か月での立ち上がりに直結する。

### 2-3. 追い風：デジタル化・AI導入補助金2026

- 旧IT導入補助金が **「デジタル化・AI導入補助金2026」** に改称され、**生成AIツールの導入費用が明確に対象化**
- 補助額 **1者あたり最大450万円**、補助率 **1/2**（小規模事業者は賃上げ要件等で**最大4/5**）
- 申請には**「IT導入支援事業者」とのパートナーシップが必須**

→ 顧客の実質負担を1/2〜1/5にできる。**成約率を構造的に引き上げる最強の営業カード**であり、同時に「支援事業者登録」という参入障壁を自分側に作れる（§9 フェーズ3）。

### 2-4. 「1人でこの規模」の実在事例

| 事例 | 規模 | 示唆 |
|---|---|---|
| Marc Lou（仏・ソロ） | マイクロSaaS4本並行で**年商約1.5億円**（$1,032,000、2025年） | 1人×複数プロダクトで1億は到達可能 |
| Pieter Levels / Photo AI | 従業員ゼロで**MRR $132,000（約1,580万円）**を18か月で達成 | AI×ソロ運営のストック収益の上限は高い |
| Base44（イスラエル・ソロ） | 6か月で25万ユーザー → Wixが**$80M**で買収 | 出口も存在する |
| iDM（日本・個人開発） | 月額4,000円 × 約70アカウント ≒ **MRR30万円弱** | 日本のニッチSaaSの現実的な初速はこのライン |

**重要な読み方**：海外事例は「上限の証明」、日本事例は「初速の現実」。本案は**サービス収益で日本の現実的初速を突破してからSaaSに乗せる**ことで、この2つのギャップを埋める設計にしている。

## 3. 事業候補5案の比較検討

年商1億が狙えるAI副業ジャンルを5案に絞り、条件別にスコアリングした（5点満点）。

| 案 | AI自動化/無人化 | 市場1億+ | 3か月立上げ | 初期投資の低さ | 成長性 | 合計 |
|---|---|---|---|---|---|---|
| **A. AI可視性（GEO/LLMO）サービス→SaaS** | 5 | 4 | **5** | 5 | **5** | **24** |
| B. バーティカル・マイクロSaaS | 5 | 4 | 2 | 5 | 4 | 20 |
| C. AI電話/チャット自動応答の導入代行・代理店 | 3 | 4 | 4 | 5 | 3 | 19 |
| D. AIコンテンツメディア（アフィリエイト/広告） | 4 | 3 | 1 | 5 | 2 | 15 |
| E. AIショート動画・SNS運用代行 | 2 | 3 | 4 | 5 | 3 | 17 |

### 各案の判断理由

**B. マイクロSaaS（次点・フェーズ2で統合）**
条件適合は高いが、**3か月では売上が立たない**のが致命的。日本の個人開発SaaSの現実解はMRR30万円弱（iDM）で、そこに至るまでに通常1年以上かかる。→ **本案では「Aで顧客と課題を掴んでからSaaS化する」形で吸収**し、単独では選ばない。

**C. AI電話/チャット自動応答**
市場は伸びている（AI予約システムは世界10兆円規模、患者予約管理AIはCAGR 27.64%）が、**プロダクト側が既にコモディティ化**。アイブリー月額3,980円、ミライAI月額4,980円、fondesk IVR月2,980円と価格が崩れており、個人が自前SaaSで戦う余地は薄い。代理店モデルは**取り分が小さく1億に届きにくい**。→ 本案の**アップセル商材として仕入れる**のが正解（§4-3）。

**D. AIコンテンツメディア**
初期投資は最小だが、**まさにゼロクリック（60%）で殴られている側**。今から参入するのは沈む船に乗る行為。除外。

**E. AI動画・SNS運用代行**
受注は取りやすいが、**編集・確認・修正が人間の手に残り無人化できない**。案件が増えるほど自分の時間が溶ける典型的な労働集約。除外。

**A を選ぶ決め手**：5案の中で唯一、**「商材そのもの（診断レポート）が営業ツールを兼ねる」**。これにより広告費ゼロで商談を作れ、3か月要件と低投資要件を同時に満たす。さらに納品物がデータとテキストのみなので、**納品工程の100%がLLMで自動化できる**唯一の案でもある。

## 4. 事業設計

### 4-1. 誰に売るか（ターゲット・ニッチ）

**第1ターゲット：地域密着かつ検索依存度が高く、1件あたりのLTVが大きい業種**

| 優先度 | 業種 | 選定理由 |
|---|---|---|
| ◎ 1st | **士業（税理士・社労士・行政書士）** | 集客の8割が検索。「顧問料 相場」「助成金 申請」等がAIに丸ごと奪われている。顧問契約LTVが年60〜120万円あるため月10〜20万円の投資判断が速い。同業紹介コミュニティが強く**横展開が効く** |
| ◎ 1st | **クリニック・歯科・自由診療** | 広告規制でリスティングが打ちづらく、検索・口コミ依存が構造的。自由診療1件の単価が高くROI説明が容易 |
| ○ 2nd | **BtoB専門商材の中小メーカー・商社** | 「〇〇 メーカー おすすめ」でLLMに列挙されるか否かが商談数に直結。予算が大きい |
| ○ 2nd | **リフォーム・工務店・不動産** | 案件単価が数百万円。1件受注で年間費用を回収できるためROI訴求が最強 |

**まず士業1業種に絞る。** 理由：①同じプロンプトセット・同じ改善テンプレートが全顧客に使い回せる＝**自動化の効率が最大化**、②業界内紹介が回る、③「この業界専門」という差別化が、既に40社以上いるLLMO対策会社との**正面衝突を回避**する。

## 5. 「従業員不在」を成立させる自動化アーキテクチャ

本案の核心。以下5レイヤーを構築すれば、**人間の稼働は「商談」と「例外対応」のみ**に圧縮される。

```
┌─ L1 収集 ────────────────────────────────────────┐
│ 業種別プロンプト集(200〜300問)を各AI検索に定期投入    │
│ ・OpenAI / Gemini / Perplexity は公式API経由        │
│ ・AI Overviews はSERP取得API等の正規サービス経由      │
│ → 自社・競合の「引用有無 / 言及順位 / 引用元URL」を記録 │
└──────────────────────────────────────────────────┘
                    ↓
┌─ L2 分析 ────────────────────────────────────────┐
│ LLMに「なぜ引用されないか」を構造化診断させる          │
│ ・不足トピック / エンティティ定義の欠落               │
│ ・schema.org 構造化データの不備                      │
│ ・第三者言及(サイテーション)の不足                    │
│ → JSONで欠落項目リストを出力                         │
└──────────────────────────────────────────────────┘
                    ↓
┌─ L3 生成 ────────────────────────────────────────┐
│ 改善アセットを自動生成                               │
│ ・FAQ / 用語定義 / 比較表コンテンツ草案               │
│ ・JSON-LD（FAQPage, Service, LocalBusiness 等）      │
│ ・Googleビジネスプロフィール投稿文                    │
└──────────────────────────────────────────────────┘
                    ↓
┌─ L4 納品 ────────────────────────────────────────┐
│ レポートHTML/PDF自動生成 → 月次で自動メール送付        │
│ 顧客用ダッシュボード（Next.js + Supabase）           │
└──────────────────────────────────────────────────┘
                    ↓
┌─ L5 営業 ────────────────────────────────────────┐
│ ターゲットリストに対し L1〜L4 をバッチ実行            │
│ →「御社は競合5社中4位でした」という無料診断書を生成    │
│ → 問い合わせフォーム/DM/郵送で送付（オプトイン遵守）   │
└──────────────────────────────────────────────────┘
```

**技術スタック（すべて既存・低コスト）**：Next.js + Supabase + Vercel / n8n（ワークフロー） / Claude API + OpenAI API / Stripe（決済） / Resend（メール）

**人間が残る作業**：初回商談（週2〜3件・各30分）、月次の例外対応（1社あたり15分程度）、四半期の戦略更新。**30社運用で週の実働は約8時間**と試算。副業として成立するライン。

## 9. リスクと対策

| # | リスク | 深刻度 | 対策 |
|---|---|---|---|
| 1 | **AI事業者の利用規約**：ChatGPT等のUIをスクレイピングで自動操作するのは規約違反リスクが高い | **高** | **必ず公式API、または正規のSERP/AI Overviews取得サービスを利用する。** UI自動操作は行わない。これはコスト増（1社月3,000円程度）を受け入れる前提で設計済み |
| 2 | **特定電子メール法**：無差別メール営業は違法 | **高** | 広告メールはオプトイン取得後のみ。初回接触は**問い合わせフォーム／郵送DM／SNS DM／紹介**で行う（郵送DMを初期投資に計上済み） |
| 3 | **競合の増加**：LLMO対策会社は既に40社超 | 中 | 士業特化＋価格帯を月5〜15万円に置き、大手（月20〜80万円）と直接競合しない。さらにSaaS化で価格競争の下限を自分で作る |
| 4 | **AI検索アルゴリズムの変動**：指標が急に無意味になる | 中 | 単一指標に依存せず「引用有無・言及順位・引用元・流入」の複合指標で契約。契約書に**成果保証を書かない**（順位保証は不可） |
| 5 | **顧客の成果不実感による解約** | 中 | 月次レポートで「AI検索経由の指名検索数」「問い合わせ数」まで追い、ビジネス成果に翻訳して見せる。初月に必ず1つ可視の改善を出す |
| 6 | **本業の就業規則** | 要確認 | 副業可否・競業避止を先に確認。住民税は普通徴収を選択。年間20万円超で確定申告、売上1,000万円超でインボイス・消費税の検討 |
| 7 | **1人稼働の上限** | 中 | サービス契約は40社を上限と定め、それ以上はSaaSへ誘導。上限到達後は業務委託（雇用ではない）で例外対応のみ外注 |
| 8 | 補助金の要件変更 | 低 | 補助金は「あれば強い」カードとして扱い、事業の前提には置かない。IT導入支援事業者登録は売上が立った後に申請 |

## 10. なぜ「サービス→SaaS」の順番が正しいのか

| | いきなりSaaS | 本案（サービス先行） |
|---|---|---|
| 初売上まで | 6〜12か月 | **4〜6週間** |
| 顧客課題の把握 | 推測で作る（外す） | **有料顧客から直接得る** |
| 開発する機能 | わからない | **手作業で30回納品して判明した工程を自動化** |
| 資金 | 自己資金を溶かす | **サービス売上が開発費を賄う** |
| 3か月要件 | 満たせない | **満たせる** |

「マイクロSaaSは魅力的だが3か月では立ち上がらない」という §3 の分析への回答が、この順番である。**手作業で30社納品した経験そのものが、SaaSの仕様書になる。**
