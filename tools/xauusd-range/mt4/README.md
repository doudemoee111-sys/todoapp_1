# MT4 Expert Advisor

`XAUUSD_RangeLevels.mq4` draws the daily range forecast on an MT4 chart as
horizontal lines with price labels.

**It places no orders.** There is no `OrderSend`, `OrderClose` or `OrderModify`
call in it.

It is an Expert Advisor rather than an indicator because MQL4 does not allow
`WebRequest()` from a custom indicator.

## Setup

1. Copy `XAUUSD_RangeLevels.mq4` to `MQL4\Experts\` and compile it with F7 in
   MetaEditor. (A `.ex4` cannot be built on Linux, so it ships as source.)
2. Tools → Options → Expert Advisors: tick **Allow WebRequest for listed URL**
   and add `https://raw.githubusercontent.com`.
3. Tick **Allow automated trading** — MT4 needs it to run any EA.
4. Attach it to an XAUUSD chart.

## The feed

`latest.txt`, regenerated by `export_mt4_levels.py` and fetched from

```
https://raw.githubusercontent.com/doudemoee111-sys/todoapp_1/refs/heads/claude/funny-mayer-vcwsjx/tools/xauusd-range/mt4/latest.txt
```

Pipe-delimited with a fixed field count per record type, because MQL4 has no
JSON parser and a hand-rolled one is the usual thing that breaks:

```
V2
META|generated_at|<UTC ISO>
META|symbol|XAUUSD
INFO|<conv>|<key>|<value>
LEVEL|<conv>|<kind>|<coverage>|<ASCII label>|<price>
```

Labels are ASCII so no codepage can mangle an object's text.

A run that cannot quote one convention carries that convention's previous
records over rather than dropping them: the 07:38 JST run cannot quote the
`utc` set, whose previous close prints at 09:00, and an Exness terminal would
otherwise have nothing to draw. The carried records keep their own `session`
and `data_end_jst`, so the EA's comment shows how old they are.

## Why two number sets

The daily high and low depend on where the broker's server clock puts the day
boundary, so the feed carries both:

| conv | server clock | bar turns over (JST) | e.g. |
|---|---|---|---|
| `nyclose` | GMT+2/+3, follows US DST | 07:00 winter / 06:00 summer | Axiory |
| `utc` | GMT+0 fixed, no DST | 09:00 all year | Exness |

Measured over the same 10 years, the two agree on both extremes on 68.0% of
sessions overall but only 54.0% of the last 250, so the wrong set is a real
error, not a rounding difference.

The EA picks a set from the server's own offset: `TimeCurrent() - TimeGMT()`
rounded to hours, `>= 1` → `nyclose`, else `utc`. `TimeGMT()` derives GMT from
the PC clock, so a badly set local clock mis-detects; the `InpConv` input
forces either set.

## Inputs worth knowing

- `InpConv` — Auto, or force `nyclose` / `utc`.
- `InpRefreshMinutes` — how often it refetches (default 15).
- The `InpShow*` flags pick which lines appear. Defaults: forecast box 50% and
  80%, the conditional 80% box, previous session high/low/close, and
  pivot/R1/S1. The 70% and 90% boxes, R2/R3/S2/S3 and the 20-day high/low are
  off until switched on.
- `InpLabelShiftBars` — how far right of the newest bar the labels sit.
- `InpLabelColumnBars` — extra offset for a label that would collide with the
  one above it. MT4 objects do not move out of each other's way, so levels
  within 2.8% of the drawn span step into a second column.

`WebRequest` is synchronous, so each refresh blocks the terminal's EA thread
for up to `InpTimeoutMs`. The default 5 s timeout every 15 minutes is not
noticeable; a very short refresh interval would be.
