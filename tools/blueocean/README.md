# blueocean — 軸1＋軸2 統合ツール

[提案④ 補論](../../docs/business-plan/proposal-04-cross-border-export/DROPSHIP-ANALYSIS.md) で提示した
**軸1（リサーチの向きを逆にする）** と **軸2（無在庫を需要検知センサーとして使い、当たりだけ有在庫化する）**
を1本のパイプラインに統合したツールです。

---

## なぜこの2つは「組み合わせる」必要があるのか

調査の過程で、設計を決定づける制約が見つかりました。

> **eBayの Marketplace Insights API（落札実績の取得）は、主要パートナー以外に開放されていません。**

つまり個人セラーは「何がいくらで売れたか」を外部データとして買えません。
一方、**Browse API（現在出品中の検索）は公開されており、個人でも使えます。**

| 欲しいデータ | 取得手段 | 個人が使えるか |
|---|---|---|
| 競合の出品数・価格帯 | **Browse API** | **使える** |
| 落札実績（何が売れたか） | Marketplace Insights API | **使えない** |

**軸1だけでは「競合がいない」ことは分かっても「売れる」ことは分かりません。**
競合ゼロは、需要がないから誰も出していないだけかもしれない。

ここを埋めるのが軸2です。**自分の出品の反応（閲覧・ウォッチ・販売）が、
個人が手に入れられる唯一の需要データになります。**

```
軸1  Browse APIで「競合が少ない」を判定  →  だが「売れる」かは分からない
                     ↓
              少量で出品して反応を見る
                     ↓
軸2  閲覧・ウォッチ・販売から需要を確定  →  当たりだけ有在庫化
                     ↓
              その実績が次の軸1の判定材料になる（ループ）
```

**2つは別々の施策ではなく、データの欠落を互いに埋め合う1つのループです。**
だからツールとして統合する意味があります。

## 使い方

### 仕入上限の逆算（まずこれを触ってください）

```bash
python -m blueocean.cli margin --price 200 --cost 12000
```

```
市場 ebay_us / セラーレベル above_standard / 売価 $200.00
目標利益率 20% を満たす仕入上限（税込）: 12,749 円
必要な「売価 ÷ 仕入」倍率: 2.35 倍

--- 内訳 ---
  売価                30000
  手数料               -5460
  関税                -3750
  送料                -3000
  梱包                 -200
  仕入               -12000
  消費税還付              1091
  利益                 6681
  利益率               22.3%
```

重量・寸法を渡さない場合は、市場ごとの固定値（概算）が使われます。
**実運用では必ず `--weight-g` と寸法を渡してください**（次節）。

市場とセラーレベルを変えると、難易度が変わることが確認できます。

```bash
python -m blueocean.cli --market shopee_sea margin --price 200      # 1.41倍
python -m blueocean.cli --level below_standard margin --price 200   # 2.79倍
python -m blueocean.cli --no-tax-refund margin --price 200          # 免税事業者
```

### 送料：重量と寸法から出す

送料は市場ごとの固定値ではなく、**課金重量**から計算します。

```bash
python -m blueocean.cli --market ebay_us ship --weight-g 900 --length-cm 30 --width-cm 25 --height-cm 20
```

```
=== 送料見積もり（ebay_us = zone4）===
実重量 900g / 寸法 30x25x20cm

  epacket     2,915円   課金重量    900g
  ems         5,300円   課金重量    900g
  parcel      6,144円   課金重量   2500g（容積 2500g） ← 容積課金
  courier    11,313円   課金重量   3000g（容積 3000g） ← 容積課金
```

固定送料をやめた理由は2つあります。

1. **料金は重量区切りで階段状に上がる。** 950gと1,050gでは1段違います。
   梱包後に100g超えて1段上がると、その差はそのまま利益から消えます。
2. **嵩張るものは容積重量で課金される。**

   ```
   容積重量(g) = 縦cm × 横cm × 高さcm ÷ 除数 × 1000
   ```

   除数は手段ごとに違います（クーリエ 5,000／国際小包 6,000）。
   そして **EMSは容積重量を採りません（実重量のみ）。**
   このため、軽くて嵩張る荷物では **EMSがクーリエを逆転して最安になる**ことがあります。
   固定送料ではこの逆転が見えず、常に誤った手段を前提に採算を組むことになります。

`margin` にも重量・寸法を渡せます。

```bash
python -m blueocean.cli margin --price 200 --cost 12000 \
    --weight-g 400 --length-cm 20 --width-cm 15 --height-cm 10
```

```
送料: 2,299 円（epacket / 課金重量 400g）
目標利益率 20% を満たす仕入上限（税込）: 13,520 円
必要な「売価 ÷ 仕入」倍率: 2.22 倍
```

#### 料金値の扱い（重要）

既定の料金表は、**公表値として確認できた金額（アンカー）と、その間を刻み幅で内挿した推定値**が
混ざっています。推定値には見積もり時に「推定値」の警告が付きます。

**内挿値のまま仕入判断に使わないでください。**
[日本郵便の公式料金計算](https://www.post.japanpost.jp/cgi-charge/) で
実際に使う地帯・重量帯を確認し、CSVで差し替えて運用します。

```bash
python -m blueocean.cli --rates data/rates.csv ship --weight-g 900
```

```csv
zone,max_weight_g,jpy
zone3,1000,4650
zone3,2000,5900
```

差し替えれば、課金重量・階段料金・手段比較という計算構造はそのまま使えます。

#### 米国宛ての取扱い

米国宛てを選ぶと、次の警告が出ます。

> 2025年8月のデミニミス（$800免税）撤廃を受け、日本郵便は物品を含む小形包装物・国際小包・
> EMS(物品)の引受を一時停止しました。2026年4月14日以降、米国税関が認証した事業者のアプリで
> 関税を事前納付すれば、指定郵便局で引受再開。

**その手当てが済むまで、米国宛ての見積もりは UGX / FedEx / DHL で行ってください。**
提案④の試算は郵便を前提にしていたので、米国比率が高い計画ではここが効きます。

### 軸1：出品候補を判定する

```bash
python -m blueocean.cli axis1 --candidates data/candidates.sample.csv --out plan.csv
```

```
[BLUE ] 105.5  競合   2  利益率 28.2%  Konica Hexanon AR 40mm F1.8
           - 競合 2件。値下げ圧力を受けにくい
           - 需要の裏付け：近縁モデルの落札あり
[PROBE] 120.2  競合   0  利益率 29.2%  山下達郎 FOR YOU 帯付 LP
           - 競合0件だが需要の裏付けが無い。少量で反応を試す（軸2へ）
[EXCL ]   0.0  競合  41  利益率  n/a  限定フィギュア 2016年版（外箱付き）
           - 除外：容積重量 2500g（実重量 900g）が上限 2000g を超過。軽いが嵩張るため送料で採算が崩れる
[EXCL ]   0.0  競合   9  利益率  n/a  Makita cordless driver 18V with battery
           - 除外：リチウム電池内蔵で航空輸送規制

[送料の注意] 米国宛て：2025年8月のデミニミス（$800免税）撤廃を受け、日本郵便は
             物品を含む小形包装物・国際小包・EMS(物品)の引受を一時停止した。（後略）
```

**`FIG-001` の除外が、送料を重量・寸法で計算するようにした効果です。**
実重量900gは上限2,000g以内ですが、外箱込みで30×25×20cmあるため容積重量は2,500g。
実重量だけを見ていると通ってしまい、送料で利益が消えます。

判定は5種類です。

| 判定 | 意味 | 次の行動 |
|---|---|---|
| `BLUE` | 競合が少なく、需要の裏付けもある | 最優先で出品 |
| `PROBE` | 競合は少ないが需要が未確認 | **少量で出して軸2で確かめる** |
| `THIN` | 採算が目標に届かない | 見送り（仕入値が下がれば再評価） |
| `RED` | 競合過多 | 見送り |
| `EXCLUDE` | 規制品・重量超過・低単価 | 対象外 |

**競合ゼロを自動的に `BLUE` にしないのが、このツールの肝です。**
「誰も出していない＝売れない」可能性を必ず残し、`PROBE` として少量検証に回します。

### 軸2：出品後の反応から次の一手を決める

```bash
python -m blueocean.cli axis2 --observations data/observations.sample.csv \
    --total-orders 120 --seller-cancellations 5
```

```
[PROMOTE] LENS-002   34日 / 閲覧 142 / ウォッチ  5 / 販売1
            1件 販売済み。需要が確定したので有在庫化し、ハンドリングを1〜2日に短縮する
[REPRICE] VINYL-001   22日 / 閲覧  98 / ウォッチ  0 / 販売0
            閲覧98件に対しウォッチ0。露出はあるので価格が原因
[RETITLE] REEL-001   53日 / 閲覧   6 / ウォッチ  0 / 販売0
            53日で閲覧6件。露出不足。海外バイヤーが実際に打つ語彙にタイトルを組み直す
[DROP   ] FIG-001  114日 / 閲覧  21 / ウォッチ  0 / 販売0
            114日間 無反応。出品を終了して枠を空ける

[警告] 在庫切れ率 4.2% が閾値 2% を超過。Below Standard に落ちると手数料が6ポイント
      上がり、必要な仕入倍率が 2.35倍→2.79倍に悪化する。出品数を減らすこと
```

判定の意味は次のとおりです。

| 判定 | シグナル | 意味 |
|---|---|---|
| `PROMOTE` | 販売あり／期間内にウォッチ3件以上 | **有在庫化する。当たり** |
| `REPRICE` | 閲覧は多いがウォッチ0 | 露出はある。価格が原因 |
| `RETITLE` | 30日で閲覧10件未満 | そもそも見られていない。検索語を直す（軸4） |
| `DROP` | 90日無反応 | 畳んで出品枠を空ける |
| `KEEP` | 上記以外 | 観察継続 |

**在庫切れ率の警告が最も重要です。** セラー都合キャンセルが積もると Below Standard に落ち、
落札手数料に6ポイント上乗せされます。利益率20%の前提そのものが崩れるため、
このツールは毎回この数字を出します。

## データの更新

**軸1と軸2の判定ロジックは変えていません。変えたのは、そこに流し込むデータの扱いです。**

軸1が見ている数字は、放っておいても勝手に動きます。

| 動くもの | どう動くか | 影響 |
|---|---|---|
| 競合出品数 | 誰かが同じ商品を出せば増える | 数日で `BLUE` が `RED` に変わる |
| 相場 | 下がれば仕入上限が下がる | 昨日まで買えた仕入値が今日は採算割れ |
| 為替・関税・送料 | 全候補の採算が同時に動く | 判定が一斉にずれる |
| 国内在庫 | 売れて消える | 候補そのものが無くなる |

つまり**判定結果には賞味期限があります。** 一発判定を繰り返すだけでは、その賞味期限も
前回からの変化も見えません。**変化こそが行動のトリガー**なので、そこを持たないと
「毎回全件を人間が読み直す」運用になってしまいます。

### 軸1：履歴を持たせて、変化だけを読む

```bash
python -m blueocean.cli axis1 \
    --candidates data/candidates.csv \
    --history data/history.jsonl \
    --refresh \
    --ebay-client-id "$EBAY_CLIENT_ID" --ebay-client-secret "$EBAY_CLIENT_SECRET"
```

```
[鮮度の警告] 前回の取得から 14日 経っています（2026-08-09）。競合数と相場は日々動きます。

=== 前回からの変化（6件 / うち要対応 3件）===

[判定悪化] LENS-002     BLUE → RED（2026-08-09 → 2026-08-23）
             → 出品中なら価格と在庫を見直す。未出品なら見送りに回す
[採算割れ] PEN-001      仕入上限 26,000円 → 21,688円。仕入 24,000円 が上限を超えた
             → 相場・為替・送料のどれかが動いた。仕入値を下げられないなら見送る
[競合変動] LENS-002     競合 2件 → 34件（+1600%）
             → 増えているなら早く出す。値下げ競争が始まる前が勝負
[相場変動] VINYL-001    相場 $190 → $140（-26%）
[候補消滅] AMP-001      今回の候補リストに無い（前回 2026-08-09 は EXCLUDE）
```

要対応（判定悪化・採算割れ・判定改善・採算回復）が先に並びます。人間は上から読むので、
**手を打つべきものが上に来る**ようにしてあります。

| オプション | 用途 |
|---|---|
| `--history PATH` | 履歴JSONL。前回との差分を出し、今回の結果を**追記**する |
| `--refresh` | CSVに値があってもeBay側を取り直す。**定期更新はこれを付ける** |
| `--changes-only` | 変化だけを表示し、全件の判定は省く（毎週の確認用） |
| `--no-record` | 履歴に書かずに差分だけ見る（試算用） |

**`--refresh` が必要な理由。** 既定では、CSVに競合数と相場の両方が入っている候補には
問い合わせません（API未契約でも手動調査の値で動かせるようにするためです）。
ただしこの挙動には落とし穴があって、**一度手で埋めた値は放っておくと二度と更新されません。**
古い数字のまま `BLUE` と表示され続けることになります。`--refresh` はこれを打ち消します。

履歴は**追記のみ**で、既存の行を書き換えません。途中でツールが落ちても過去の履歴は壊れません。
また同じ日に2回走らせても「前回」は前の実行日のままなので、再実行で差分が消えることもありません。

推移を見るコマンドもあります。

```bash
python -m blueocean.cli history --history data/history.jsonl --sku LENS-002
```

```
=== LENS-002 の推移（3件）===

日付         判定     競合     相場   仕入上限  利益率
2026-08-09   BLUE        2 $    185     12,295   28.2%
2026-08-16   PROBE      12 $    180     11,887   27.0%
2026-08-23   RED        34 $    165     10,662   23.2%
```

**競合が増えて相場が下がっていく過程が見えます。** 一発判定では最後の行しか見えません。

### 軸2：観測CSVは追記して育てる

観測CSVは**毎週の行を足していく**運用です。同じSKUの行が何本並んでも構いません。

```csv
sku,listed_on,observed_on,views,watchers,sold
LENS-002,2026-07-20,2026-08-16,118,3,0
LENS-002,2026-07-20,2026-08-23,142,5,1   ← 追記
```

ツールが**SKUごとに最新の1行だけを判定対象**にし、1つ前の行を前回比の計算に使います。

```
[PROMOTE] LENS-002   34日 / 閲覧 142 / ウォッチ  5 / 販売1
            1件 販売済み。需要が確定したので有在庫化し、ハンドリングを1〜2日に短縮する
            前回比（7日）: 閲覧 +24 / ウォッチ +2 / 販売 +1
[DROP   ] FIG-001   114日 / 閲覧  21 / ウォッチ  0 / 販売0
            114日間 無反応。出品を終了して枠を空ける
            前回（2026-08-16／7日前）から動きなし  ← 停滞
```

累計142件の閲覧が、先週+3件なのか+80件なのかで意味はまるで違います。
**判定ルール自体は累計値のまま変えていません**（前回比の有無で結論は変わりません）。
前回比は、同じ判定の中で優先順位を付けるための材料です。

### ブラウザ版

ブラウザ版にも同じ差分機能があります（Python版と9パターンで出力が完全一致することを確認済み）。
軸1タブの「**今回の結果を記録する**」を押すと、その時点の判定が**このブラウザに**保存され、
次回の判定時に前回からの変化が出ます。**記録は端末から出ません**（サーバーには送りません）。
プライベートモード等で保存できない場合は、履歴なしとして通常どおり動きます。

## 商品リサーチはどこまで自動化されているか

**「リサーチ全体が自動」ではありません。** 工程ごとに分けると次のとおりです。

| 工程 | 自動化 | 実装 | なぜそうなっているか |
|---|---|---|---|
| ① 国内の仕入候補を**見つける** | **手動** | なし | メルカリ・ヤフオク等のスクレイピングは規約に反しうるため、既定にしない |
| ② eBayの**競合出品数・相場**を取る | **自動** | `sources/ebay_browse.py` | Browse APIは個人でも使える |
| ③ 落札実績（何が売れたか）を取る | **不可** | — | Marketplace Insights APIが主要パートナー限定。**軸2が代替する** |
| ④ 送料を重量・寸法から出す | **自動** | `shipping.py` | 課金重量・階段料金・手段比較まで計算する |
| ⑤ 採算と競合から**判定する** | **自動** | `scoring.py` | ここがツールの本体 |
| ⑥ 出品する | **対象外** | — | 既存の出品ツール（SAATS等）が担当 |
| ⑦ 出品後の反応から次の一手を決める | **自動** | `promotion.py` | Seller HubのCSVを読む |

**自動化されていないのは①だけです。** ②〜⑦は候補リストさえ渡せば機械が回します。
①を手作業に残しているのは技術的な理由ではなく、**規約上の判断**です。
公式APIや正規のデータ提供が使える仕入元が見つかれば、`blueocean/sources/` に
アダプタを足すだけで①も自動化できます（そのための抽象は `sources/base.py` に用意済み）。

**ブラウザ版にはAPI連携がありません。** 通信を一切しない設計なので、②は手入力になります。
API連携が要る運用はPython版を使ってください。

### 元データの制約

| データ | 取得方法 | 備考 |
|---|---|---|
| 競合出品数・価格帯 | **eBay Browse API** | 個人の開発者アカウントで利用可 |
| 落札実績 | Marketplace Insights API | **主要パートナー以外は不可** |
| 出品後の反応 | eBay Seller Hub のレポート | CSVでエクスポートして読み込む |
| 国内の仕入候補 | **手動CSV**（既定） | スクレイピングは規約違反になりうるため自動化しない |
| 国際送料の料金表 | **公式料金表を手動で投入** | 既定値は推定を含む。`--rates` で差し替える |
| 過去の判定 | **履歴JSONL**（`--history`） | ツールが自分で追記する。前回との差分の材料 |

**国内ECのスクレイピングは実装していません。** メルカリ・ヤフオクは規約で
「手元にない商品の出品」やデータの自動取得を制限しており、規約に適合しない取得手段を
既定にすべきではないと判断したためです。公式APIや正規のデータ提供が使える場合のみ、
`blueocean/sources/` にアダプタを追加してください。

**認証情報が無い場合は `MockSource` が使われます。** 決定的な擬似データを返すだけなので、
パイプラインの動作確認には使えますが、**判断には絶対に使わないでください**（実行時に警告を出します）。

### eBay Browse API を使う場合

```bash
python -m blueocean.cli axis1 \
    --candidates data/candidates.csv \
    --ebay-client-id "$EBAY_CLIENT_ID" \
    --ebay-client-secret "$EBAY_CLIENT_SECRET" \
    --out plan.csv
```

CSVに `market_price_usd` と `competitor_count` の両方を書いておけば、APIを呼びません。
API未契約の期間は、Terapeak等で手動調査した値を入れて運用できます。

## 設定できる前提

**関税率は流動的です。** 米国の制度はこの半年で3回変わりました（de minimis廃止 →
最高裁の違法判決 → 通商法122条 → 301条）。`blueocean/profit.py` の `DEFAULT_PROFILES`
は2026年8月時点の値なので、**運用前に必ず現在の値を確認して上書きしてください。**

```python
from blueocean.models import FeeProfile, Market
from blueocean.profit import DEFAULT_PROFILES

DEFAULT_PROFILES[Market.EBAY_US] = FeeProfile(
    market=Market.EBAY_US,
    fee_rate=0.18,        # eBay手数料の実効値
    per_order_fee_jpy=60,
    duty_rate=0.125,      # ← ここを最新の値に
    shipping_jpy=3000,    # 重量・寸法を渡さない場合のフォールバック値
    packaging_jpy=200,
)
```

**`shipping_jpy` は概算のフォールバックです。** 重量・寸法を渡せば `shipping.py` が
実際の課金重量から送料を出し、この値は使われません。

## このツールがやらないこと

- **出品そのもの** — SAATS Commerce等の既存ツールが担当します。本ツールは出品候補CSVを渡すところまで
- **国内ECの自動巡回** — 規約上の理由（上記）
- **落札実績の取得** — API制約（上記）。軸2が代替します
- **国内の仕入候補を自動で見つけること** — 規約上の理由（上記）。①だけが手作業です
- **送料の実額の保証** — 料金表は推定を含みます。公式料金表で差し替える前提です
- **定期実行そのもの** — `--history` を付けて走らせる仕組み（cron等）は各自の環境で組んでください

**既存の出品ツールと競合しません。** 既存ツールが持っていない「判断」の部分だけを埋めます。
