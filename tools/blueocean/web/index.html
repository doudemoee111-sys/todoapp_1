Blue Ocean 仕入判断ツール

目の前の1点をその場で判定し（1件だけ判定）、候補をまとめて選び（軸1）、 出品後の反応から有在庫化を判断する（軸2）。 送料は固定値ではなく、重量と寸法から課金重量を出して計算します。 リポジトリのPython版と同じ計算式をブラウザで動かします。入力はこのページから出ず、保存もされません。

前提条件—
入力するたびに自動でも再計算されます。このボタンは確認用です。

このツールは何をするものか

日本の商品を海外（eBay・Shopee）に売るとき、「その値段で買っていいか」「いくらで出すか」を 数字で決めるための道具です。手数料・関税・国際送料・消費税還付をすべて織り込んで計算します。

出品作業そのものはしません。判断だけを担当します。 出品は SAATS Commerce などの既存ツールが得意なので、そちらに任せる前提です。

始める前に用意するもの

  • 古物商許可（中古を扱うなら着手前に取得）。無許可営業は3年以下の拘禁刑または100万円以下の罰金です
  • 課税事業者の届出。輸出免税による消費税還付（税込仕入 × 10/110）が無いと、利益率20%はほぼ届きません
  • eBayアカウント（相場と競合数を自分で調べるため）
  • 1g単位のはかりとメジャー。送料は重量と寸法で階段状に変わります。目分量では判断できません

手順

  1. 1前提条件を自分の状況に合わせる ページ上部の「前提条件」を開き、市場・為替・目標利益率・セラーレベルを入れて 「この条件で全部を計算し直す」を押します。以降すべてのタブがこの条件で計算されます。 関税率は変わります。既定値は2026年8月時点の対日12.5%です。運用前に必ず最新を確認してください。
  2. 2いくらまでなら買えるかを掴む 「仕入上限の逆算」タブ。想定売価と荷姿を入れると、その値段までなら買っていいという上限が出ます。 「必要な 売価÷仕入」倍率が、その市場での難易度です。米国は関税で倍率が跳ね上がります。
  3. 3目の前の1点を判定する 「1件だけ判定」タブ。店頭やフリマアプリを見ている最中に使う画面です。 eBayで同じ商品を検索して、出品件数と価格帯を見て入力します。 eBayの検索結果に出る「1,234 results」が競合数。左メニューの Sold Items にチェックを入れると、実際に売れた価格が見えます。
  4. 4まとめて候補を選ぶ 「軸1」タブ。候補をCSVで貼り付けると5段階で判定します。 「今回の結果を記録する」を押しておくと、次回に前回からの変化（BLUE→RED、採算割れ）が出ます。 競合数と相場は日々動くので、判定結果には賞味期限があります。
  5. 5仕入れたら値段を決める 「値決め」タブ。出品価格と、Best Offer をどこまで受けられるかの一覧が出ます。 円安が止まったとき・関税が上がったときにどこで赤字になるかも出します。 Best Offer はその場で返事が要ります。出品時にこの表を控えておいてください。
  6. 6出品して、反応を見る 「軸2」タブ。eBay Seller Hub のレポートから閲覧・ウォッチ・販売数を持ってきて貼り付けます。 毎週追記していけば、最新の1行で判定し、前回からの増分も出ます。 PROMOTE が出たら当たり。無在庫をやめて手元に仕入れ、発送を1〜2日に縮めます。
  7. 7売れ残りを束ねる 「セット販売」タブ。単品では売れない在庫を売れ筋に混ぜると、送料が1回で済むぶん採算が変わります。 単価の低いものほど効きます。米国向けなら、個別に売ると赤字の構成がセットで黒字になることがあります。

「送料（重量・サイズ）」タブはいつ使うか

どの手順でも使う補助画面です。配送手段を横並びで比較できます。 軽くて嵩張るもの（衣類・外箱付きフィギュア）は容積重量で課金されるため、 EMSが逆にいちばん安くなることがあります。固定送料では見えない逆転です。

仕入値はどこに入れるのか

「軸1」タブの表の「仕入(円)」欄です。行に直接入力すると、その場で判定と仕入上限が変わります。 判定を動かせる変数は3つあり、そのうち自分で決められるのは仕入値だけなので、 ここだけは表で直に触れるようにしてあります。

1件だけ試す 「1件だけ判定」タブの「仕入価格」欄。店頭でその1点を判定するとき
まとめて見る 「軸1」タブの表の「仕入(円)」欄。候補が複数あるとき。入力すると即座に判定が変わります
CSVで入れる cost_incl_tax_jpy 列。走査の出力を読み込んでから表で埋めるのが楽です
仕入れた後 「値決め」タブの「仕入価格」欄。ここからは出品価格と値下げ幅の話になります

仕入上限を超えると、その行の上限が赤字になり判定が THIN に落ちます。 判定カードの「↕」に「仕入をあと◯円下げれば採算に乗る」と出るので、 そのまま値切り交渉の目標額として使えます。

候補はどうやって集めるのか

候補はキーワード（型番）を起点に、eBay側を引いて作ります。 条件は次の4つで、これをファイルに固定して毎回同じ条件で回します。

抽出元 ジャンル（シリーズ×形態に展開）またはキーワード一覧ファイル
絞り込み 競合 5件以下＝空き／30件以上＝過密／相場 $30未満＝低単価で除外
荷姿の仮定 現物が手元に無い段階なので、重量と寸法を仮定して送料を出します（予算の計算に効きます）
市場と目標 上の「前提条件」（市場・為替・関税・目標利益率・セラーレベル）

毎回同じ条件で抜く仕組み

条件を jobs.json に書いておくと、コマンド1本で毎回同じ条件で抽出できます。 そして2回目からは前回からの変化だけが出ます（BLUE→RED、採算割れ、競合の急増）。 条件が固定されているからこそ差分が意味を持つ、という作りです。 

python -m blueocean.cli job --config data/jobs.json --name anime-set
=== アニメ・フィギュアのまとめ売り（anime-set）===
  条件: ebay_us / セラーレベル above_standard / 目標利益率 20% / 為替 150円

  [鮮度の警告] 前回の取得から 14日 経っています（2026-08-09）。

  走査 40件 → 探す価値あり 19件
  判定 8件 → 出品対象 4件

  前回からの変化 2件（うち要対応 1件）
    [判定悪化] LENS-002     BLUE → RED（2026-08-09 → 2026-08-23）

  書き出し: out/anime-hunt.html   ← 写真つきの照合シート
  書き出し: out/anime-plan.csv    ← 出品対象

この画面でできること・できないこと

できる 抽出条件を組み立てること（軸1タブの「抽出条件をつくる」）。 設定とコマンドをそのまま出すので、コピーして Python版で実行できます
できる 抽出結果のCSVを読み込んで、仕入値を入れて判定すること
できない 抽出そのもの（eBayを検索して候補を作る工程）。 eBayのAPIを呼ぶ必要があり、この画面は外部への通信をしない設計だからです。 抽出は Python版で行ってください。

軸1の判定は、何を基準に変わるのか

判定を動かす変数は3つだけです。そして自分で動かせるのは仕入値だけです。 競合数と相場は他人が決めます。

各カードの「↕」を見てください

判定の下に、何がどう変われば裏返るかを1行で出しています。

BLUE のとき競合があと◯件増えると見送り／相場が $◯ まで下がると採算割れ
THIN のとき仕入をあと◯円下げれば採算に乗る（値切り交渉の目標額になります）
RED のとき競合が◯件以下に減れば再評価。ただし競合数は自分では動かせない
PROBE のとき需要の裏付けが取れれば BLUE。少量で出して軸2で確かめる

前回からどう変わったかを見る

軸1タブの「今回の結果を記録する」を押しておくと、次に判定したときに 前回からの変化だけが上に出ます（BLUE→RED、採算割れ、競合の急増、相場の下落）。 競合数と相場は毎日動くので、判定結果には賞味期限があります。 1週間空いたら「前回の記録から◯日経っています」と警告します。

商品の写真をどう確かめるか

型番が同じでも、世代違い・マイナーチェンジ違いがあります。 買ってから気づいたのでは遅いので、探しに行く前に見た目を確かめてください。 とくにセット販売は「何が入っているか」で値段が決まるので、写真が要ります。

このページ 各カードの「出品中の写真を見る ↗」「落札済みの写真と価格 ↗」から eBayの検索結果を開けます。実物の写真と、実際に売れた価格がそこで見られます。
このページ自体にはeBayの写真を表示できません。 公開ページは外部サイトへの画像リクエストを遮断する仕組みの上で動いているためです。
自分で撮った写真 「1件だけ判定」と「セット販売」では手元の写真を貼れます。 端末内で縮小してこの端末にだけ保存します（サーバーには送りません）。 セットの構成品を撮っておくと、出品文を書くときにそのまま使えます。
Python版 --sheet を付けると、eBayの商品写真つきの照合シート（HTML）を 書き出します。印刷して持って行くか、スマホで開いて店頭で照合する使い方です。 ローカルのファイルなので画像の制約がかかりません。

よくある外し方

  • 寸法を入れない。実重量だけで計算すると、嵩張る商品で送料が下振れします。判定が甘くなる方向に外れます
  • 梱包前の重量を入れる。緩衝材と箱で100〜300g増えます。段が1つ上がればその差はそのまま利益から消えます
  • 競合ゼロを「空いている」と読む。誰も出していないのは、売れないからかもしれません。このツールが PROBE に落とすのはそのためです
  • 米国だけを見る。関税制度はこの半年で3回変わりました。市場を切り替えて比べてください
  • 古いデータで仕入れる。競合数と相場は毎日動きます。軸1の記録機能で前回からの変化を見てください

このツールがやらないこと

  • 国内で現物を探すこと。メルカリ・ヤフオク等は自動取得を規約で制限しています。何を探すかはジャンル走査が決めますが、探すのは人の仕事です
  • 出品作業。既存の出品ツールの担当です
  • 落札実績の取得。eBayのMarketplace Insights APIは主要パートナー以外に開放されていません。だから軸2（自分の出品の反応）が唯一の需要データになります
  • 送料の実額の保証。料金表は公表値と推定が混ざっています。「推定」と出た金額は公式料金表で確認してください

損益の内訳

市場を変えるとどうなるか

市場手数料関税送料必要倍率

同じ商品でも売り先を変えるだけで難易度が変わります。米国一本足にしない理由がここにあります。

梱包後の重量と寸法を入れると、配送手段を横並びで比較します。 上の「荷物（梱包後）」の入力をそのまま使います。市場を変えると地帯が変わり、料金も変わります。

なぜ固定送料では足りないのか

  1. 料金は階段状に上がる。950g と 1,050g では1段違います。梱包後に100g超えて 1段上がると、その差はそのまま利益から消えます。
  2. 嵩張るものは容積重量で課金される。 容積重量(g) = 縦×横×高さ(cm) ÷ 除数 × 1000。 除数は手段ごとに違います（クーリエ 5,000／国際小包 6,000）。
  3. EMSは容積重量を採りません（実重量のみ）。だから軽くて嵩張る荷物では、 EMSがクーリエを逆転して最安になります。この逆転は固定送料では見えません。
料金表は暫定値です。公表値として確認できた金額（アンカー）と、その間を刻み幅で内挿した推定値が 混ざっています。推定値には「推定」と表示します。運用前に 日本郵便の公式料金計算 で実際の地帯・重量帯を確認してください。
課金重量—実重量と容積重量の大きい方

配送手段課金重量送料出典
