## 管理者からの判断

このリポジトリが、戦略側セッションとパイプライン側セッションの唯一の連絡手段
（別コンテナのため直接メッセージは届かない）。判断が必要なことはここに書く。
作業を始める前にこの節を読み、対応したら「済」と日付を追記すること。

### 2026-08-22｜既存2本の概要欄も同じ形に更新するか → 更新する。ただし章だけは条件つき

- **相互リンク・タグ・再生リストは更新してよい。** メタデータのみで再生成は不要、
  `videos.update` は50ユニットなのでクォータも問題ない。最初の2本はこれから
  最も長くインプレッションを稼ぐ在庫なので、retrofit する価値がある。
- **章（タイムスタンプ）は、その動画の実測値が残っている場合だけ入れること。**
  `result.json` には `synthesize_timed` の実測セグメントが保存されていないため、
  work_dir が消えていれば章の位置は推測になる。ずれた章は無いより悪い:
  視聴者は文の途中に飛ばされ、YouTube は最初の章マークをキーモーメントに使う。
  実測値が無ければ章は入れず、相互リンクとタグだけ更新する。
- あわせて、今後のために `result.json` へ実測セグメント（または章の開始秒）を
  保存しておくこと。次に同じ判断をするときの材料になる。

### 2026-09-09｜L2（アンビエントのみ）を出すか → 出さない（見送り確定）

8月に枠だけ作って無効のまま置き、1ヶ月運用してから決めるとしていた件。
ユーザー判断で **見送り確定**。日曜の枠は空けたままにする。

理由は2つ。

1. **L2 には解説パートが無い。** YouTube の収益化ポリシーが除外する
   「再利用コンテンツ」（反復的で、価値の付加がないもの）に最も近い形になる。
   このチャンネルは既にAI判定を1回受けており、そこへ踏み込む理由がない。
   L3 が成立しているのは、前半のオリジナルの語りが「価値の付加」の証明に
   なっているから。同じ音源を、その証明なしで出すのは別物。
2. **実測で L3 は L1 の16倍**（インプレッションあたりの再生時間）だった。
   同じ手間をかけるなら L3 を増やすほうが確実。L2 の唯一の利点は尺だが、
   それは「最後まで再生された場合」の話で、いまの課題は表示されて
   クリックされること（CTR 0.7%）のほう。

トリガー `睡眠ch L2アンビエント3h` は削除せず、無効のまま名前だけ
「見送り」に変えて残してある。将来の再検討で作り直す手間を省くため。

**再検討するとしたら**、音風景の比較結果が出る11月上旬以降。ただしその
時点でも、増やす先は L2 ではなく L3 週3本を先に検討すること。

      このブランチは睡眠・安眠チャンネル2の専用です（利用可能: sleep）。
      space / urban / mystery は別チャンネルのジャンルです。

### 2026-08-29｜定期実行がフォアグラウンドで動画生成していた（トリガー修正）

睡眠chの3トリガー（火/木/土）は `python3 run.py …` をフォアグラウンドで
実行していた。無人セッションの Bash は既定2分・最大10分で強制終了されるため、
**動画が未完成のままセッションが「正常終了」として記録される**。

記録上の所要時間:

| 実行 | 記録上の所要 | 本来必要な時間 |
|---|---|---|
| 8/25(火) L1 | 123秒 | 20〜30分 |
| 8/27(木) L3 | 101秒 | 30〜45分 |

3本とも、次のようにバックグラウンド実行＋ログ待ちに書き換えた:

    nohup python3 run.py --genre sleep --mode <mode> > /tmp/sleep_run.log 2>&1 &
    # 以後 tail で「DONE」/「scheduled publish:」を待つ。
    # 完了行が出るまでセッションを終了しない。ダミー成功にしない。

### 2026-10-05（追記）｜実測データが無いと、モデルは測定結果を捏造する

**`room` ジャンルの初回を本番前に空打ちして見つけた。** 実測データ0件の状態で台本を
作らせたところ、次のものが出てきた。

```
見出し: 測定方法と条件 / ウレタン素材の結果 / シリコン素材の結果 / ワックス素材の結果
本文  : 「夜中の騒音を遮断する効果を測定すると、約35デシベルの音を減少させることが
        確認されました」「実験では、約30デシベルの音を低減しました」
```

**誰も測っていない。** 薬機法チェックは通っている——通って当然で、デシベルの値を
でっち上げることは薬機法違反ではない。薬機法違反より悪い。**このチャンネルの名前で、
存在しない一次情報を公開することになる。** しかも、これから載せる本物の実測値と
見分けがつかない。ジャンルを切り替えた理由そのものを壊す。

**原因:** 「新しい数値を作るな」という柵は、実測データが**あるとき**にしか渡していなかった。
無いときは何も言っておらず、一方でジャンルの枠組み自体が「測った報告をしろ」と押すので、
足りないぶんをモデルが埋めた。沈黙が捏造を生んだ。

**対策（2段構え）:**

1. **`measurement.no_data_block()`** — 実測が無い回には、禁止だけでなく
   *代わりに何を作るか* を指定する。「測り方と、数字の読み方」の回にする。
   道具・置く位置・条件の揃え方・公表値の調べ方で構成し、
   「測定しました」「実験では」は一度も書かない。数値を出すなら同じ文に出典を書く。
   outline と**全章**に渡す（捏造は、何も渡していなかった第3章以降で起きた）。
2. **`measurement.fabrication_findings()`** — 検出器。`run.py` が台本生成の直後に
   走らせ、見つかれば**1回だけ書き直し**、それでも残れば**中断**する。
   1日落とすほうが、捏造を出すより安い。

   **検出器の1つ目は作り直した。** 最初に書いたものは一般的なパターンで、
   対策後の正しい台本——つまり「測り方」の回——を全面的に弾いた。
   「測定するには」「測定する際には」を捏造として拾ったため。
   見分けるのは時制と人称で、「測定する**には**」は手順、「測定し**ました**」は主張。
   いまは後者だけを明示列挙している。再現性のあるものだけを拾う。
   2つ目（数値）も、**結果として提示された数値だけ**に絞った。
   「42デシベルという値」は説明、「28デシベルまで下がりました」は報告。
   後者だけが出典を要る。寸法（cm・kg）は対象外——「枕元から30センチに置く」は
   指示であって結果ではなく、そこで誤検出を出すと警告そのものが読まれなくなる。

   **実測6文を6件検出、正しい10文を0件誤検出**で固定した（対策前の実出力と、
   対策後の実出力の両方から文を取っている）。

検出器は実測データが**無いときだけ**走る。あるときは数値は本物で、
「測定しました」は事実だから。

**この件の一般形:** 生成を止める柵は、材料があるときより**無いときのほうが要る。**
材料が無い状態こそ、モデルが埋めにくる。
