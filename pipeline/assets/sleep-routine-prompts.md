# 睡眠チャンネル 定期実行トリガー（Routines）

## 2つのチャンネルの境界線（最初に読む）

同じ `pipeline/` のコードを、**2つの別チャンネル**が使っています。
資格情報が混ざると、片方の動画がもう片方のチャンネルに投稿されます。
実際に一度、共有していたOAuthクライアントのシークレット再発行で既存チャンネルの
自動投稿が停止しました。**分離は運用ルールではなくコードと設定で担保します。**

| | 既存チャンネル | 睡眠チャンネル |
|---|---|---|
| ジャンル | `space` / `urban` / `mystery` | `sleep` |
| GCPプロジェクト | 既存のもの | **`sleep-channel`（専用・新規）** |
| OAuthクライアント | 既存のもの | **専用に新規作成** |
| `GOOGLE_TTS_API_KEY` | 既存のもの | **専用に新規作成** |
| Claude Code 環境 | 既存のもの | **専用に新規作成** |
| `EXPECTED_CHANNEL_ID` | 既存チャンネルのID | 睡眠チャンネルのID |
| ショートパイプライン | 使う | **使わない** |

### 触ってはいけないもの

睡眠チャンネルの構築・保守で、**既存プロジェクトのOAuthクライアントには一切触らないこと。**
とくに次の操作は、既存チャンネルの自動投稿を即座に停止させます。

- 既存クライアントの**シークレットの再発行・削除**
- 既存クライアントの**削除・作り直し**
- 既存環境の `YOUTUBE_*` の上書き

シークレットが読めない、といった理由で再発行したくなった場合は、
**再発行せずに新しいクライアント（できれば新しいプロジェクト）を作ってください。**

### EXPECTED_CHANNEL_ID による自動ガード

各環境に、その環境が投稿してよいチャンネルのIDを入れておきます。

```
EXPECTED_CHANNEL_ID=UCxxxxxxxxxxxxxxxxxxxxxx
```

設定すると、`preflight` と `--check-auth` の両方で認証済みチャンネルと照合し、
**食い違っていればアップロード前に中断します**（生成の20分を無駄にせず、1ユニットで判定）。
未設定の環境では何もしないので、既存環境の挙動は変わりません。

チャンネルIDは `--check-auth` が表示します。

```
$ python3 run.py --check-auth
[check-auth] OK — 認証成功。投稿先チャンネル: 「(チャンネル名)」
[check-auth] channelId: UCxxxxxxxxxxxxxxxxxxxxxx
```

**この値を両方の環境に設定してください。**既存チャンネル側にも入れておけば、
今後どちらの作業でも取り違えが起きなくなります。タイトルではなくIDで照合しているので、
チャンネル名を変更しても誤検知しません。

---

`GENRES["sleep"]` は**専用チャンネル**に投稿します。専用のGCPプロジェクト・専用のOAuth
クライアント・専用のClaude Code環境を用意し、既存チャンネルの資産とは一切共有しません。

## 認証：専用プロジェクトで一式を新規発行する

| 環境変数 | 睡眠チャンネル用 |
|---|---|
| `YOUTUBE_CLIENT_ID` | **専用プロジェクトで新規作成** |
| `YOUTUBE_CLIENT_SECRET` | **専用プロジェクトで新規作成** |
| `YOUTUBE_REFRESH_TOKEN` | **新チャンネルで認可して取得** |
| `GOOGLE_TTS_API_KEY` | **専用プロジェクトで新規作成**（Cloud Text-to-Speech API のみに制限） |
| `EXPECTED_CHANNEL_ID` | **睡眠チャンネルのID**（`--check-auth` が表示） |
| `OPENAI_API_KEY` / `STABILITY_API_KEY` | 既存を流用（Googleと無関係のため） |

OAuth Playground の ⚙ で**この専用プロジェクトのクライアントID/シークレットを指定**してから、
**新しいブランドチャンネル**で認可します。3点とも同一クライアントから出るため、
「3点一致の鉄則」は自動的に満たされます。

専用プロジェクトにする理由はもう1つあります。**YouTube Data API のクォータは
プロジェクト単位で1日10,000ユニット**で、共有すると既存チャンネルのリサーチ
（`search.list` は1回100ユニット）が走った日に上限を超え、睡眠チャンネルの
その日の投稿が丸ごと落ちます。

## 週次スケジュール

`--rotate-date` は使いません（睡眠は単一ジャンルのため）。曜日ごとにモードを固定します。

| 曜日 | モード | 中身 | cron (UTC) | 起動 JST | 公開 JST |
|---|---|---|---|---|---|
| 火 | `narrated` | L1 解説 8〜12分 | `0 8 * * 2` | 17:00 | 21:00 |
| 木 | `guide` | L3 解説10分＋アンビエント2h | `0 7 * * 4` | 16:00 | 21:00 |
| 土 | `narrated` | L1 解説 8〜12分 | `0 8 * * 6` | 17:00 | 21:00 |
| 日 | `ambient` | L2 マスキング音源 3h | `0 7 * * 0` | 16:00 | 21:00 |

`next_publish_at()` は最低3時間のリードを要求します。上の起動時刻はいずれも
それを満たします。`ambient` と `guide` を1時間早く起動するのは、長時間音源の
合成に数分〜十数分かかるためです（実測：3時間で約6分30秒、出力180MB）。

**1ヶ月目は L2（日曜）のトリガーを無効にしておきます。** 先に L1・L3 で
「解説チャンネル」としてのトピック認識を作ってから L2 を解放しないと、
量産型コンテンツ（Inauthentic Content）判定のリスクを自分で作ることになります。

## トリガー・プロンプト（OWNER/REPO/BRANCH を置換して使用）

```
これは毎日自動実行される動画生成・予約投稿タスクです。人間の確認は不要。全自動で最後まで完了させ、最後に必ず結果を報告してください。

【重要】このセッションはまっさらな新セッションで、作業ディレクトリにコードがありません。まず自分でリポジトリをクローンしてください（認証はプロキシ経由で通ります）。

【手順（この順序を厳守）】
1. リポジトリ取得:
   if [ -d ~/REPO/.git ]; then cd ~/REPO && git fetch origin BRANCH && git checkout BRANCH && git pull origin BRANCH; else git clone --branch BRANCH https://github.com/OWNER/REPO.git ~/REPO && cd ~/REPO; fi
   取得に失敗したら中断してgitエラーを報告。
2. 依存導入: cd ~/REPO && bash pipeline/setup.sh
3. ★先に認証を検証: cd ~/REPO/pipeline && python3 run.py --check-auth
   - 「[check-auth] OK」が出て、かつ投稿先チャンネルが【睡眠チャンネル名】であることを確認できた場合のみ手順4へ。
   - 別のチャンネル名が表示された場合、または ChannelMismatch で中断した場合は、環境変数が別チャンネルのものになっている。動画を作らず中断して報告。
   - 環境に EXPECTED_CHANNEL_ID が設定されていれば、手順4の preflight でも同じ照合が走り、食い違えば投稿前に中断する。
4. 生成＋予約投稿:
   （火・土）python3 run.py --genre sleep --mode narrated
   （木）    python3 run.py --genre sleep --mode guide
   （日）    python3 run.py --genre sleep --mode ambient
5. 最後に必ず報告: 認証結果 / モード / タイトル / 尺(分) / 予約公開時刻(JST) / 動画URL。
   薬機法チェックで中断した場合は、指摘内容を全文そのまま報告すること。
   失敗時は「どの工程で落ちたか＋エラー全文」。

【厳守】
- 鍵・トークンはこの環境に設定済み。値は絶対に表示しない。
- 薬機法チェック(compliance)が3回のリライトで通らず中断した場合、チェックを回避して投稿してはならない。中断して報告する。
- エラー時にダミー音声・プレースホルダ画像・別モードへの安易な切替で「成功」に見せかけない。
- ambient / guide は生成に十数分かかる。アップロード完了までセッションを終了しない。
```

## 手動での確認コマンド

```bash
# 認証と投稿先チャンネルを確認（チャンネル名と channelId が出る）
python3 run.py --check-auth

# L2 を短尺で試作（アップロードしない）— まずこれで音を耳で確認する
python3 run.py --genre sleep --mode ambient --seconds 300 --no-upload

# L1 を1本だけ試作
python3 run.py --genre sleep --mode narrated --no-upload

# 薬機法チェックの辞書だけを単体テスト（APIキー不要）
python3 compliance.py

```

## 尺を伸ばすときの目安（実測値）

| 尺 | 音源合成 | 動画エンコード | 出力サイズ |
|---|---|---|---|
| 3時間 | 約 6分30秒 | 約 8秒（尺によらず一定） | 約 180 MB |
| 8時間 | 約 17分（推定） | 約 8秒 | 約 480 MB |

動画は60秒ぶんを1回だけエンコードして `-stream_loop` で複製するため、
**尺を伸ばしてもエンコード時間は増えません**。増えるのは音源合成の時間だけです。

3時間で安定して回ることを確認してから `AMBIENT_SECONDS=28800` で8時間に伸ばしてください。
